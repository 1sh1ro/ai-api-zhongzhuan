METHODOLOGY

收录原则、核验方法与排序规则

这个页面说明每个数字是怎么来的，以及它不能说明什么。

收录原则

  • 只收录公开可访问的站点，至少能打开官网或注册页。
  • 每条报价必须有来源链接和核验日期，没有来源的数字不录入。
  • 不收录需要提供敏感凭据才能看到的页面，不在公开页面展示 API Key、Cookie、后台地址。
  • 推广链接会明确标注，是否带推广参数不影响排序。

报价的六种口径

口径含义是否参与排名
绝对单价折算站点公布每百万 Token 的人民币或美元单价，直接与官方价相除参与
分组倍率折算站内分组倍率乘以已披露的充值系数参与
维护者折算原始资料已经算好的有效倍率，原样记录参与
站内分组倍率只有分组倍率，充值系数未公开不参与，只显示原值
按次计费图片、视频、语音按张、按秒计价不参与
免费额度按次数或时间窗口发放的免费用量不参与

综合倍率怎么算

人民币口径下，综合倍率 = 站点单价 ÷（官方美元单价 × 汇率），按输入:输出 = 3:1 加权。汇率采用 6.70，并记录在 data/pricing-config.json。1.00x 等于官方价，0.10x 就是官方价的一折。

为什么只在同一个模型内比较

不同模型的官方价、缓存价、长上下文档位和上游成本都不同，一个站点在国产模型上给 0.001x、在 Claude 上给 0.15x 很常见。把不同模型的最低倍率放在一张榜上，等于拿 A 模型的最低价去比 B 模型的最低价，结论会失真。

因此本站的排名分两层：模型报价榜先选一个模型，只排这个模型下各站点的倍率；模型页也只在同一个模型内排序。站点综合评分里的价格维度，采用「同模型相对位置」的平均值，每个模型里最好的站点记 1、最差记 0，再按覆盖模型数折减，避免只在一个模型上便宜的站点拿高分。

核验等级

  • 站方价格接口：读取站点公开的 pricing JSON，可复算。
  • 官网价格页：页面公开标价，人工摘录。
  • 用户截图 / 用户提交：只能人工核对，会标「待核验」。
  • 未独立核验：只有运营方声明，不参与排名。

综合评分怎么算

站点评分满分为 100 分，只使用本站已有数据计算，规则版本为 composite-score-v1。每个站点的评分明细都可以在站点页看到。

维度满分计算方式
价格竞争力40该站在每个可比模型里的相对位置（最好 1、最差 0）取平均，覆盖少于 3 个模型时按比例折减
数据透明度20口径统一的报价条数 ÷ 该站报价总数
来源可追溯15来源权重均值折算 10 分，最新核验在 30 天内加 5 分、90 天内加 3 分
覆盖广度15收录模型数最多 10 分，覆盖系列数最多 5 分
信息完整度10官网、注册入口、简介、标签、来源链接等可核验字段

等级划分：75 分以上为 A，60 到 74.9 为 B，45 到 59.9 为 C，45 以下为 D。评分只反映价格、透明度和信息完整程度，不包含可用率、延迟和模型真实性，因为没有这些数据时不能给出那部分分数。

排序规则

模型报价榜先选定一个模型，只统计该模型下口径统一的报价，按综合倍率升序。至少有两个站点报价的模型才会出现在选择器里。站点索引按综合评分排序，评分中的价格部分已经按模型内相对位置计算，不会拿不同模型的倍率直接相加。规则版本为 model-scoped-asc.v2。

这份数据不能说明什么

  • 首页能打开，不代表 API 可用，也不代表模型是宣称的那个。
  • 价格低，不代表稳定；限流、排队、突然关站都可能发生。
  • 官方基准价会变，促销价有到期时间，历史报价只代表记录当时的状态。
  • 本站不运营、不担保任何第三方服务，不对交易结果负责。

更正与反馈

发现价格错误、站点关停或模型归属不对，可以在 GitHub 仓库提交 Issue。每条更正都会更新对应报价的核验日期。

访问统计

首页底部显示当天的访问人数。计数按浏览器本地存储去重，同一浏览器当天只计一次，按上海时区分日，不写 Cookie，不记录 IP、页面路径或个人信息。计数由第三方 Abacus 计数器提供，只用于了解站点大致访问量。

人气榜

人气榜统计从本站跳转到各中转站的出站点击，按自然月累计，同一浏览器每天对同一站点只计一次。它反映本站读者的兴趣，不代表站点的注册量、活跃用户或成交。注册人数只有站点自己知道，本站无法检测；如果站点愿意提供转化数据，可以单独标注来源。

点击计数由第三方 Abacus 提供，只记录站点编号和月份，不记录点击者身份。人气榜不参与自然排名，也不影响站点评分。
